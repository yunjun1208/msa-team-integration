## 최종 구성과 처리 흐름

사용자 → HTTPS ALB → 프런트엔드/Nginx 및 API Gateway → 회원·상품·주문 서비스 → RDS MySQL.

주문 서비스는 상품 재고 예약/확정/해제와 주문 상태를 관리한다. 완료 이벤트는 Outbox에서 SNS로 보내고, SQS → Lambda → SES로 주문 메일을 전달한다. Lambda의 이벤트 중복 억제 정보는 DynamoDB에 보관한다. Argo CD는 Git의 이미지 선언을 EKS에 반영하고, Prometheus/Grafana 및 CloudWatch는 상태를 관찰한다.

GitHub Actions는 변경 서비스를 선택해 검사·테스트·이미지 게시를 수행한다. 테스트된 digest를 릴리스 PR로 검토한 후 병합한다. 배포 검증은 EKS 접근 제한을 유지한 채 VPC 내부 CodeBuild에서 실행한다.

## 데이터 보존 종료와 실제 복원

10월 19일 Stop 결과는 `0 added, 0 changed, 81 destroyed`였다. 전체 AWS 자원 삭제가 아니라 데이터·복구 자료를 보존하는 대상 지정 종료였다.

보존 대상은 원격 Terraform state, ECR 이미지, 상품 S3, 로그, SNS/SQS, 이메일 dedup DynamoDB, 인증서, RDS 수동 snapshot, 모니터링 EBS 및 로컬 복구 자료다. 보존 저장소에는 비용이 계속 발생한다. 과거에 안내한 하룻밤 비용은 추정이며 실제 청구액 검증이 아니다.

10월 20일 Resume에서 새 VPC/EKS 및 RDS를 구성하고 보존 데이터를 연결했다. Grafana PVC 소유권 문제를 수정한 뒤 `RESUMED AND VERIFIED`와 `PASS: revision, images, availability, TLS, HTML, product API`를 확인했다. 기존 일반 회원으로 로그인하고 원래 상품 #1 재고 7개, 원래 주문 #1/#2가 남아 있음을 화면에서 확인했다. 상품 이미지와 기존 Grafana 대시보드·현재 지표도 조회했다.

복구 파일은 같은 Windows PC/사용자에 종속된 DPAPI 암호화 백업이다. `.overnight`, 개인 tfvars, Windows 사용자 프로필을 보존해야 한다. 이를 다른 PC에서 바로 복구할 수 있다고 보장하지 않는다.

## 이메일·관리 운영 설정 점검

서울 리전의 사용자 AWS CLI 읽기 전용 점검 결과:

- `ProductionAccessEnabled=false`: SES 샌드박스 유지.
- `SendingEnabled=true`, `EnforcementStatus=HEALTHY`.
- 점검 당시 한도: 24시간 200통, 초당 1통. 최근 24시간 3통으로 조회됨. 이는 오늘 새 주문 이후 최종 누적량을 의미하지 않는다.
- 인증된 EMAIL_ADDRESS 1개, Verification SUCCESS. DOMAIN identity는 조회되지 않아 자체 도메인 DKIM 인증 완료로 판정할 수 없다.
- 메일 Lambda의 SQS 연결 Enabled. 점검 당시 큐 대기/처리 중 개수는 각각 0이었다. 성공한 동시 주문 전의 시점 값이다.
- Grafana는 기존 로그인 세션으로 홈에 접근됨. 사용자가 초기 비밀번호 변경 완료를 확인했다.

현재 구성은 검증된 수신자에게 보내는 발표·실습 용도로 해석한다. 일반 고객 대상 운영에는 발신 주소/도메인 결정, 도메인 identity와 DNS DKIM 인증, 필요 시 MAIL FROM/SPF·DMARC 정렬 검토, IAM 발신 범위와 Lambda 발신 주소 변경, 반송·불만 처리 및 AWS 프로덕션 접근 승인이 별도로 필요하다. 이번 작업에서는 신청·도메인 변경·발신자 전환을 하지 않았다.

AWS 설명: [샌드박스 해제/프로덕션 접근](https://docs.aws.amazon.com/ses/latest/dg/request-production-access.html), [identity 생성·도메인 인증](https://docs.aws.amazon.com/ses/latest/dg/creating-identities.html). 도메인 인증만으로 샌드박스가 자동 해제되는 것은 아니다.

## 새로 준비한 검증 도구

이 공유 폴더의 도구는 별도 검증 산출물로 함께 게시한다. 운영 앱이나 기존 CI 실행 경로에 자동 연결하지 않았다. 도구의 대상 계정/context 보호 설정은 실행 전에 확인한다.

| `test_product_recovery_drill.py` | 모의 테스트 8개. 복구 실패 오보고 방지, UID·context 보호, scale 실패에도 정책 복원 시도 |

## 운영자가 이어받을 때

사용자 Desktop 체크아웃은 마지막 확인 당시 `fix/checkout-failure-message`의 b70e2e4였다. GitHub에서 진행한 후속 변경을 받기 전에는 과거 로컬 코드로 종료·복원하지 않는다.

프로젝트 폴더에서 작업 내용을 먼저 확인하고 최신화한다. 미커밋 변경이 있으면 자동 reset/stash하지 말고 보존한다.

```powershell
git status
git switch main
git pull --ff-only origin main
```

종료가 필요한 날은 최신 `OVERNIGHT-RECOVERY.md`를 읽고 같은 Windows PC·계정에서 준비 단계와 보존 계획을 검토한다. 다음은 명령의 역할을 안내하는 예시이며 지금 즉시 종료하라는 지시가 아니다.

```powershell
powershell -ExecutionPolicy Bypass -File scripts/ops/Manage-Overnight.ps1 -Action Prepare
powershell -ExecutionPolicy Bypass -File scripts/ops/Manage-Overnight.ps1 -Action Stop
# 종료 완료 후 다음 시작 시:
powershell -ExecutionPolicy Bypass -File scripts/ops/Manage-Overnight.ps1 -Action Resume
```

종료 전 GitHub 게시·검증 자동화를 유지할지 중지할지 운영 절차에 맞춰 확인한다. 복원 후 GitHub 변수 `ENABLE_AWS_PUBLISH`, `ENABLE_DEPLOY_CHECKS`, Argo revision, 이미지 digest, 로그인·기존 주문·상품·지표를 확인한다. 오늘 두 변수는 true로 운영 검증했다. 현재 계정의 비용 전체가 0이라고 해석하지 않는다.
