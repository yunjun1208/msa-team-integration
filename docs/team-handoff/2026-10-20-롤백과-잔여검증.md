## 장애 주입 실습 준비

`product_recovery_drill.py`는 기본 실행 시 읽기 전용 계획을 확인한다. 별도 --execute 옵션에서만 상품 deployment를 0으로 내려 장애를 만들며, 기본 90초 후 원래 복제본 수와 Argo automated.enabled 값을 복원한다. DB·Secret·Terraform·다른 서비스는 변경하지 않는다. --recover는 남겨 둔 상태 파일로 복구만 재실행한다.

- 계정/리전이 명시된 정확한 EKS context 검사, Argo Synced/Healthy/실행 작업 없음 검사, ApplicationSet 소유 앱 거부, 정상 product replica 수 확인.
- 변경 전에 원래 replica 수와 auto-sync enabled 값, 리소스 UID를 파일로 보존한다. Kubernetes 리소스가 재생성됐으면 다른 리소스를 덮어쓰지 않는다.
- 실패·응답 유실에도 finally에서 복구를 시도한다. scale 복원 실패여도 auto-sync 복원을 별도로 시도한다. 복구 실패를 성공으로 보고하지 않는다.
- 모의 테스트 8개 통과. 이것은 실제 클러스터 장애·복구 성공 증거가 아니다.
- 운영 상품 조회·주문 재고 처리에 일시 영향이 있으므로, 읽기 전용 계획 확인 후 점검 시간을 정해 --execute를 실행한다. 실행 프로세스를 강제 종료하지 않는다. 복구 실패 시 --recover를 실행하고 결과를 확인한다.
- 참고: [Argo CD 자동 동기화 정책](https://argo-cd.readthedocs.io/en/stable/user-guide/auto_sync/).
